# Fase 1 · Base de la infraestructura (Tríada) · Plan de implementación

> **Para agentes:** SUB-SKILL OBLIGATORIA: usar `superpowers:subagent-driven-development` para ejecutar este plan tarea por tarea. Los pasos usan casillas (`- [ ]`) para el seguimiento.

**Objetivo:** 3 backends Flask con métricas Prometheus detrás de Nginx (round robin + `stub_status`), orquestados con Docker Compose y validados por CI en cada PR.

**Arquitectura:** Un solo `app.py` construido en una imagen y levantado 3 veces con distinto `INSTANCE_ID`. Nginx es el único servicio publicado al host (8080) y reparte a `backend1..3:5000` dentro de la red `so-net`. GitHub Actions corre calidad (ruff, pytest, hadolint) y una prueba de humo con el stack levantado.

**Stack:** Python 3.12 · Flask · prometheus_client · gunicorn · Nginx 1.27-alpine · Docker Compose · GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-18-fase1-base-design.md` (léelo antes de empezar). Acuerdos con otras fases: `docs/CONTRATO.md`. Reglas del proyecto: `CLAUDE.md`.

## Restricciones globales

- Rama de trabajo: `fase1-base` (sale de `develop`; el PR va a `develop`). Nunca editar en `main` ni `develop`.
- **Claude no ejecuta git que escriba** (commit, push, tag, PR). En cada paso «Proponer commit» muestra los comandos y **se detiene** hasta que Manuel confirme.
- Código simple, legible por un junior: sin abstracciones propias, sin loops ingeniosos, comentarios breves en español. Identificadores de código en español salvo los nombres de métricas.
- Ningún nombre del contrato cambia sin actualizar `docs/CONTRATO.md` y avisar a Manuel.
- `requirements.txt` solo con `==`. Versiones de ruff, pytest y hadolint también fijas.
- Puertos: solo `8080:80` publicado. Backends (5000) y `stub_status` (8081) nunca al host.
- gunicorn: `--workers 1 --threads 4`.
- Comandos de ejemplo para Manuel en PowerShell (`curl.exe`). El CI usa bash.
- Documentación al cerrar cada tarea: su sección del README y su sección del informe (Google Doc en `CLAUDE.md` → Informe; skill `anthropic-skills:google-workspace`, reemplazar el texto gris «Pendiente · Manuel …» de esa sección, en Times New Roman 12 negro, sin tocar saltos ni diseño de página). Donde falte una captura: `[CAPTURA: qué mostrar · comando]`.

## Foco de revisión

1. **Ruta inexistente** (`/no-existe`): responde 404 y se cuenta con `ruta="otra"`, sin crear una serie por URL → prueba en Tarea 1.
2. **Tráfico de Prometheus y del healthcheck**: `/metrics` y `/health` no suman en `http_requests_total` → prueba en Tarea 1.
3. **Backend detenido en pleno tráfico**: el cliente sigue recibiendo 200 desde los otros dos → verificación en Tarea 3.
4. **Puerto 8080 ocupado** (el `lab-proxy` anterior usa 8080): se detecta y se resuelve antes de levantar → paso en Tarea 3.
5. **Archivos editados en Windows (CRLF)**: el CI en Linux no falla por finales de línea → verificación en Tarea 4.

### Tarea 1: Backend Flask con métricas

**Rol:** Senior Python Backend Engineer (implementa) · Senior SRE (revisa métricas contra el contrato).
**Skills:** `superpowers:test-driven-development`, `superpowers:verification-before-completion`.

**Archivos:**
- Crear: `backend/app.py`, `backend/requirements.txt`, `backend/tests/test_app.py`

**Interfaces:**
- Produce: `app` (Flask) e `INSTANCE_ID` (str) en `backend/app.py`; gunicorn arranca `app:app`.
- Produce métricas: `http_requests_total{instancia,metodo,ruta,codigo}` (Counter) y `http_request_duration_seconds{instancia,ruta}` (Histogram, buckets por defecto).
- Produce rutas: `GET /` → `{"instancia", "mensaje", "contenedor"}`; `GET /health` → `{"estado": "ok", "instancia"}`; `GET /metrics` → texto Prometheus; `GET /lento?ms=<n>` → `{"instancia", "espera_ms"}` (defecto 500, acotado 0–2000).

- [ ] **Paso 1: Preparar entorno local**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```
Si no hay Python 3.12 en el host, correr las pruebas dentro de `python:3.12-slim` con `docker run --rm -v "${PWD}/backend:/app" -w /app python:3.12-slim sh -c "pip install -r requirements.txt pytest==<v> && python -m pytest tests -v"`.

- [ ] **Paso 2: `requirements.txt`** con `flask`, `gunicorn`, `prometheus-client` en versión exacta estable (`pip index versions <paquete>`). Instalar junto con `pytest` y `ruff` fijos.

- [ ] **Paso 3: Escribir las pruebas que fallan** en `backend/tests/test_app.py`

```python
from prometheus_client import REGISTRY

from app import INSTANCE_ID, app

cliente = app.test_client()


def valor(metrica, etiquetas):
    # Lee el valor actual de una métrica; 0 si todavía no existe
    return REGISTRY.get_sample_value(metrica, etiquetas) or 0


def test_inicio_devuelve_la_instancia():
    respuesta = cliente.get("/")
    assert respuesta.status_code == 200
    assert respuesta.get_json()["instancia"] == INSTANCE_ID


def test_health_responde_ok():
    respuesta = cliente.get("/health")
    assert respuesta.status_code == 200
    assert respuesta.get_json() == {"estado": "ok", "instancia": INSTANCE_ID}


def test_cada_peticion_suma_en_el_contador_y_en_la_duracion():
    etiquetas = {"instancia": INSTANCE_ID, "metodo": "GET", "ruta": "/", "codigo": "200"}
    antes = valor("http_requests_total", etiquetas)
    antes_duracion = valor("http_request_duration_seconds_count", {"instancia": INSTANCE_ID, "ruta": "/"})
    cliente.get("/")
    assert valor("http_requests_total", etiquetas) == antes + 1
    assert valor("http_request_duration_seconds_count", {"instancia": INSTANCE_ID, "ruta": "/"}) == antes_duracion + 1


def test_metrics_y_health_no_se_cuentan():
    cliente.get("/metrics")
    cliente.get("/health")
    for ruta in ["/metrics", "/health"]:
        assert valor("http_requests_total", {"instancia": INSTANCE_ID, "metodo": "GET", "ruta": ruta, "codigo": "200"}) == 0


def test_ruta_desconocida_se_cuenta_como_otra():
    respuesta = cliente.get("/no-existe")
    assert respuesta.status_code == 404
    assert valor("http_requests_total", {"instancia": INSTANCE_ID, "metodo": "GET", "ruta": "otra", "codigo": "404"}) >= 1


def test_metrics_expone_el_formato_de_prometheus():
    texto = cliente.get("/metrics").get_data(as_text=True)
    assert "http_requests_total" in texto
    assert "http_request_duration_seconds_bucket" in texto


def test_lento_espera_lo_pedido():
    respuesta = cliente.get("/lento?ms=50")
    assert respuesta.status_code == 200
    assert respuesta.get_json() == {"instancia": INSTANCE_ID, "espera_ms": 50}


def test_lento_acota_valores_fuera_de_rango():
    assert cliente.get("/lento?ms=-5").get_json()["espera_ms"] == 0
    assert cliente.get("/lento?ms=abc").get_json()["espera_ms"] == 500
    assert cliente.get("/lento?ms=9999").get_json()["espera_ms"] == 2000
```

- [ ] **Paso 4: Comprobar que fallan**
Run: `cd backend; python -m pytest tests -v` → FAIL (`ModuleNotFoundError: app`).

- [ ] **Paso 5: Implementar `backend/app.py`**
- `INSTANCE_ID = os.environ.get("INSTANCE_ID", "sin-id")`.
- Las dos métricas con los nombres y etiquetas de **Interfaces**.
- `@app.before_request` guarda `time.perf_counter()` en `g.inicio`; `@app.after_request` (si la ruta no es `/metrics` ni `/health`) calcula `ruta = request.url_rule.rule if request.url_rule else "otra"`, incrementa el contador con `codigo=str(respuesta.status_code)` y observa la duración; devuelve la respuesta.
- `/metrics` devuelve `generate_latest()` con `CONTENT_TYPE_LATEST`. `contenedor` = `socket.gethostname()`.
- `/lento`: `ms = request.args.get("ms", default=500, type=int)`, luego `ms = max(0, min(ms, 2000))`, `time.sleep(ms / 1000)`.

- [ ] **Paso 6: Comprobar que pasan**
Run: `python -m pytest tests -v` → 8 passed (unos 3 s por las esperas de `/lento`). `ruff check .` → `All checks passed!`

- [ ] **Paso 7: Documentar**
- Informe → sección **Aplicación backend**: qué hace cada ruta (incluida `/lento` y para qué sirve), el middleware, las dos métricas y sus etiquetas, decisiones (por qué Flask, por qué `instancia` y no `instance`, por qué no se cuentan `/metrics` ni `/health`).
